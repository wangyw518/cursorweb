# 05 · 表设计（MBS 自有库）

> 范围：**仅 MBS 自有库**（消费者域 + 交易域 + 营销/内容/触达 + 横切设施）。
> 供给/履约（房源/房态/价格/指南/占房/booking/合规）**不在此建表**，走 PMS 真源；MBS 仅以 `pms_booking_id` 等指针关联。
> DB：MySQL 8 / InnoDB。规范（遵循 InnoDB OLTP 最佳实践）：
> - 主键 `BIGINT UNSIGNED AUTO_INCREMENT`；对外业务号（`*_no`）用二级唯一索引，不做主键。
> - 全表 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`。
> - 尽量 `NOT NULL`；时间用 `DATETIME`（非 `TIMESTAMP`），统一 `created_at/updated_at`。
> - 状态用 `TINYINT` + 注释常量（避免 ENUM，取值见 `04-架构设计.md` 第 6 节）。
> - 金额一律**分**（`BIGINT`/`INT UNSIGNED`），不用浮点。
> - 敏感字段（证件号/手机号）**加密存储**：`VARBINARY` 存密文 + `CHAR(64)` 存 HMAC 盲索引（可等值查不可反解）。
> - 索引：等值列在前、范围/排序列在后（最左前缀）；列表查询用游标分页。
> - 表名统一 `c_` 前缀（consumer）。

DDL 未显式写 `created_at/updated_at` 处，默认均含：
```sql
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
```

## 一、用户域

### c_user — C 端用户（真源）
```sql
CREATE TABLE c_user (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  uid          CHAR(20)        NOT NULL COMMENT '对外用户号(雪花/短码)',
  mobile_cipher VARBINARY(256) NULL     COMMENT '手机号密文',
  mobile_hash  CHAR(64)        NULL     COMMENT '手机号HMAC盲索引',
  nickname     VARCHAR(64)     NOT NULL DEFAULT '',
  avatar_url   VARCHAR(512)    NOT NULL DEFAULT '',
  gender       TINYINT         NOT NULL DEFAULT 0 COMMENT '0未知1男2女',
  birthday     DATE            NULL,
  status       TINYINT         NOT NULL DEFAULT 1 COMMENT '1正常0停用9注销',
  register_channel VARCHAR(16) NOT NULL DEFAULT '' COMMENT 'wxmp/alipay/h5',
  last_login_at DATETIME       NULL,
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_uid (uid),
  UNIQUE KEY uk_mobile_hash (mobile_hash),
  KEY idx_status_created (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='C端用户';
```

## 二、发现/内容（收藏·足迹·搜索·只读快照）

### c_listing_snapshot — 房源只读检索快照（非真源）
```sql
CREATE TABLE c_listing_snapshot (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  pms_listing_id BIGINT UNSIGNED NOT NULL COMMENT 'PMS房源/房型ID(真源)',
  property_id  BIGINT UNSIGNED NOT NULL,
  title        VARCHAR(128)    NOT NULL DEFAULT '',
  cover_url    VARCHAR(512)    NOT NULL DEFAULT '',
  city_code    VARCHAR(12)     NOT NULL DEFAULT '',
  district_code VARCHAR(12)    NOT NULL DEFAULT '',
  lat          DECIMAL(10,7)   NULL,
  lng          DECIMAL(10,7)   NULL,
  min_price    INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '起价(分)',
  facilities   JSON            NULL COMMENT '设施标签(冗余便于筛选)',
  score        DECIMAL(3,2)    NOT NULL DEFAULT 0 COMMENT '评分冗余',
  review_count INT UNSIGNED    NOT NULL DEFAULT 0,
  status       TINYINT         NOT NULL DEFAULT 1 COMMENT '1上架0下架',
  synced_at    DATETIME        NOT NULL,
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_pms_listing (pms_listing_id),
  KEY idx_city_status_price (city_code, status, min_price),
  KEY idx_geo (district_code, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='房源只读检索快照(来自PMS同步, 非真源)';
```
> 价格/房态**不以快照为准**，下单必须实时查 PMS。`min_price`/`score` 仅列表展示与排序用。

## 十、设计要点回顾

1. **交易域全在 MBS**（`c_order` 系列 + `c_payment/c_refund`），`pms_booking_id` 单指针连到 PMS 履约域——回答了"用户产生的数据尽量全放 B 端"。
2. **库存/房态不落 MBS**：`c_listing_snapshot` 仅检索展示，价格/可订性实时查 PMS，占房事务在 PMS，杜绝超卖与双写。
3. **敏感数据合规**：证件号/手机号密文 + 盲索引；证件照原文只在 PMS 私有空间；`c_traveler_profile` 只做便捷副本。
4. **金额全用分**、状态用 `TINYINT` + 文档常量、台账类（积分/支付/退款）**只增不改**便于对账审计。
5. **可靠性内建**：`c_idempotency_key` + `c_outbox_event` 保证"支付成功→占房""状态→订阅消息"的幂等与最终一致。
6. **可扩展**：订单/流水类为写多热表，PK 单调自增，未来可按 `created_at` 分区或按 `user_id` 分片迁 Vitess/PlanetScale。
