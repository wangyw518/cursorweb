# mbs-web-mp「久窝朋赞会」全新 C 端 · 架构与表设计

> 依据：`joywo` 仓库 `docs/mbs-web-mp-prototype` 分支下 `jiuwo-docs/product/prototype/mbs-web-mp` 的**真实高保真原型**（uni-app / Vue3，3 个 Tab + 17 个页面 + 问栖 AI 找房悬浮球）逐屏拆解而成。
> 目标：把 `mbs-web-mp` 做成一套**自有数据、可独立演进的完整会员制 C 端**，而不是 BFF 转发；基础配置放 PMS，用户产生的数据尽量全部放 MBS（C 端后端）。

---

## 1. 原型是什么（产品定位）

`mbs-web-mp` = **久窝自营民宿品牌（栖舍）的会员制小程序「久窝朋赞会」**。它不是"住后服务工具"，而是一个**从种草 → 直订 → 支付 → 入住 → 会员成长 → 复购**的完整消费闭环。三个 Tab：

- **入住**（首页/住中）：当前在住卡（智能门锁/到店导航/管家）、AI 今日行程、周边礼遇（咖啡 8 折 / 晨间轻食 / 接送站 / 展览）。
- **预定**（发现/搜索）：城市+关键词+日期+入住条件搜索、灵感目的地、随心住广告位、**问栖 AI 找房悬浮球**（语音/文字自然语言找房）。
- **会员**（会员中心）：平台会员等级、门店会员、随心住、积分/优惠券/收藏、常用服务。

### 三大产品支柱（决定架构与表设计）

1. **自营直订**：浏览 → 房源详情 → 订单填写(checkout) → 在线支付 / 随心住抵扣 → 出行。C 端自持交易订单。
2. **双级会员 + 权益体系**
   - **平台会员**（银卡/金卡/铂金/黑金）：**成长值**驱动、**全平台通用**，享房价折扣（9.5→8 折）、旅行礼遇、优先服务。成长值来源：消费 1 元 +1、入住 1 晚 +100、带图点评 +50；每年 12/31 结算。
   - **门店会员**（初见/悦享/臻选/御尊）：**在该门店累计入住晚数**驱动、**各门店独立**，享门店会员价（可与平台会员**叠加**）、**门店积分**、**门店储值余额**、专属礼遇。"入住或到店关注任意门店即自动成为该门店会员"。
   - **随心住（FlexiPass）**：门店的**预存房晚月券**——一次性预付买 N 晚，30 天有效、可选生效日、本店多房型通用、临期无房可申请延期。属**预付/储值型商品**。
3. **AI 行程**：问栖 AI 找房（语音/文字）+ AI 行程助手（出发地/目的地/天数/同行/风格/节奏/住宿偏好 → 多日行程）+ 首页"今日行程"+ 保存的行程。

配套能力：**安心住**（装了平台智能门锁的门店，支持蓝牙 / 碰一下开锁）、管家服务、收藏与足迹、优惠券与礼品卡、发票、客服。

> 原型**未包含**登录注册、实名人脸核验、账号注销等页面——这些复用 PMS/现有 mbs 能力（实名证件在 checkout 采集，核验走 PMS）。

## 2. 核心结论（回答你的两个问题）

**问题①：不要只做 BFF 转发，要做完整体系 —— 怎么落地？**

把 `mbs-api` 从"薄 BFF"升级为**"消费者域 + 交易域 + 会员营销域"的业务系统**：拥有自己的库、领域模型、支付/钱包/幂等/outbox 等设施；只在**供给侧真源**（房源/房态/价格/入住指南配置/门锁）上读/调 PMS。

**问题②：基础配置放 PMS，其他用户产生的数据是否可以全部放 C 端（MBS）？**

**结论：可以，而且这个原型让答案非常明确——会员、成长值、积分、储值、随心住、券、礼品卡、收藏、足迹、AI 行程、评价、订单、支付，全部放 MBS。只有两类留在 PMS 做真源：**

| 数据 | 真源 | 说明 |
|---|:---:|---|
| 房源 / 房型 / 房间 / 设施 / 价格 / 房态 / 入住指南配置 / 门锁·安心住 | **PMS** | "基础配置 + 货架"，C 端只读/调 |
| 入住/履约单（占房、办入住退房、房态占用）、实名核验、公安上报 | **PMS** | 履约与合规口径唯一 |
| C 端账号/资料、交易订单、支付、退款、发票 | **MBS** | 交易域真源 |
| **平台会员 / 门店会员 / 成长值 / 平台积分 / 门店积分** | **MBS** | 会员体系真源 |
| **随心住月券 / 门店储值余额 / 优惠券 / 礼品卡**（预付资金） | **MBS** | 钱包与权益台账（预付资金需资金/发票合规） |
| 收藏 / 足迹 / 搜索历史 / 评价 / 站内信 / 反馈 | **MBS** | 消费者内容 |
| **AI 行程 / 偏好 / 问栖会话 / POI 内容** | **MBS** | C 端 AI 域（与 PMS 的经营 AI 无关） |

**两处关键接缝（除此之外 C 端数据不依赖 PMS 落库）：**

1. **下单/随心住核销 → PMS 占房**：C 端交易订单支付成功（或随心住抵扣），MBS 幂等调 PMS "确认占房"拿到 `pms_booking_id`。这与"美团订单进 PMS"是同一套履约模型。
2. **PMS 履约完成 → MBS 会员成长**：客人离店/订单完成后，PMS 发"入住完成"事件，MBS 据此累加**成长值 / 门店入住晚数 / 积分**，驱动会员升级。即 **PMS 是"入住事实"的真源，MBS 是"会员权益"的真源。**

> 一句话：**"货 + 履约 + 门锁"归 PMS；"人、单、钱、券、住晚数换来的会员权益、AI 行程"全归 MBS。** 定价时 PMS 出房价基线，MBS 叠加（平台折 × 门店折 + 券 + 随心住/储值抵扣）算应付。

详见 [`03-数据归属-PMS-vs-MBS.md`](./03-数据归属-PMS-vs-MBS.md)。

## 4. 原型页面一览（映射锚点）

| Tab / 页面 | 关键功能 | 主归属 |
|---|---|---|
| Tab 入住 `checkin` | 在住卡（门锁/导航/管家）、AI今日行程、周边礼遇 | PMS(履约/门锁)+MBS(行程/礼遇) |
| Tab 预定 `booking` | 搜索(城市/日期/条件)、灵感目的地、随心住广告、问栖AI球 | PMS(货)+MBS(搜索/AI) |
| Tab 会员 `member` | 平台会员、门店会员、随心住、积分/券/收藏、常用服务 | MBS |
| `city` | 城市+热点选择 | MBS |
| `results` | 搜索结果列表 | PMS(货)+MBS |
| `store` | 门店主页(自营)、在售房型、随心住、管家 | PMS(货)+MBS(会员/随心住) |
| `room` | 房源详情、安心住、随心住卡、设施/周边/评价 | PMS(货)+MBS(收藏/评价) |
| `checkout` | 订单填写(日期/人数/住客/身份证)、支付方式(在线/随心住)、费用明细 | MBS+PMS(占房/实名) |
| `pass` | 随心住购买(档位/生效日/立省/规则) | MBS |
| `member-levels` | 平台等级与权益、成长值规则 | MBS |
| `store-member` | 门店会员详情(等级/积分/储值/随心住/晋级) | MBS |
| `orders`/`order-detail` | 交易订单列表/详情、取消/再订/发票/联系门店 | MBS |
| `favorites` | 收藏 | MBS |
| `ai-planner`/`ai-result`/`ai-trips` | AI 行程助手/结果/已保存行程 | MBS |
| 组件 `ai-seek-ball`（问栖） | 语音+文字 AI 找房 | MBS |
| 组件 `safe-stay-tag`（安心住） | 智能门锁门店标 | PMS(门锁)+MBS(展示) |
