# 01 · 功能拆分（全新 C 端功能点清单）

> 粒度：功能点（feature）。每项标注 **归属**（PMS 真源 / MBS 真源 / FE 前端）与依赖。
> 归属图例：`MBS` = MBS 自有库真源；`PMS` = 读/调 PMS；`FE` = 纯前端；`MBS+PMS` = MBS 主导、需调 PMS。
> 拿到原型稿后，用本清单逐屏打勾即可完成映射。

---

## E1 · 账号与登录（MBS）

| 功能点 | 归属 | 关键接口/说明 | 依赖/风险 |
|---|---|---|---|
| 微信小程序一键登录（code2session→openid/unionid） | MBS | `POST /mbs/v1/auth/wx-login` | 微信 appid/secret |
| 支付宝小程序一键登录 | MBS | `POST /mbs/v1/auth/alipay-login` | 支付宝配置 |
| 手机号验证码登录/注册（首次自动注册） | MBS | 复用现有 mbs-api 登录 | 阿里云短信 |
| 手机号绑定 / 授权手机号（微信/支付宝快捷授权） | MBS | 绑定后统一为一个 C 端用户 | 多端 unionid 合一 |
| 资料管理（昵称、头像、性别、生日） | MBS | `PUT /mbs/v1/profile` | |
| 多端账号合一（微信/支付宝/手机号→同一 user） | MBS | unionid + mobile 归并策略 | 账号合并冲突处理 |
| 账号注销（合规） | MBS | 复用现有 `account/deactivate` | 数据清理策略 |
| 登录态 / 刷新令牌 / 设备与推送 token | MBS | JWT + refresh；`c_user_device` | |

## E2 · 首页与发现（MBS 运营 + PMS 货架）

| 功能点 | 归属 | 关键接口/说明 | 依赖/风险 |
|---|---|---|---|

| 浏览足迹 | MBS | `c_browse_history` | |

> 说明：房源"货架"的真源始终是 PMS；MBS 可建 `c_listing_snapshot` 只读快照用于检索/筛选性能，由 PMS 变更事件或定时同步刷新，**不作真源**。

## E4 · 下单与支付（MBS 交易域 + PMS 占房/报价）· 最重

| 功能点 | 归属 | 关键接口/说明 | 依赖/风险 |
|---|---|---|---|
| 下单页（房型、入住/退房日期、间数、人数） | FE+PMS | 读实时报价 | |
| 填写/选择入住人（从常用入住人带入） | MBS | `c_traveler_profile` 带入 | 实名便捷副本 |
| 选券 / 会员优惠计算 | MBS | 券与会员规则；应付 = PMS 报价 − MBS 优惠 | 优惠叠加规则 |
| 价格明细（房费/税费/优惠/应付） | MBS+PMS | 冻结报价快照到交易单 | 价格一致性 |
| **提交订单 → PMS 预占(hold)** | MBS+PMS | `POST /public/bookings/hold`（幂等） | **超卖/并发** |
| 创建交易订单（待付款） | MBS | `c_order` + `c_order_item` + `c_order_occupant` | |
| 微信支付 / 支付宝支付（下单、调起、回调) | MBS | `c_payment`；支付回调幂等 | 对账 |
| **支付成功 → PMS 确认占房** | MBS+PMS | outbox 可靠调用 `bookings/confirm`；存 `pms_booking_id` | **最终一致** |
| 支付结果页 / 未支付超时自动取消 + 释放 hold | MBS+PMS | 定时任务 + `bookings/release` | |
| 订单改期 / 加人（视政策） | MBS+PMS | 视一期范围，可后置 | |

## 附：与现有 `mbs-web` / `mbs-api` 的复用关系

| 现有能力 | 在新 C 端的处置 |
|---|---|
| 手机号验证码登录、账号注销、App 版本、反馈 | **复用 + 增强**（加微信/支付宝登录、多端合一） |
| 入住指南、实名、同住人、自助退房、呼叫房东 | **复用**（改从交易订单进入） |
| HMAC 公开接口签名、BFF 转发 | **保留**，作为 MBS 调 PMS 的通道 |
| —（交易、支付、券、会员、评价、消息、收藏） | **全新建设**，MBS 自有库 |
