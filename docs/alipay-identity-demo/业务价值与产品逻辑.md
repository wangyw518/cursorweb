# 业务价值与产品逻辑

> 用于支付宝小程序「用户实名三要素」能力申请填写。内容对应审核要求：业务背景与理由、授权功能与字段、授权后服务、拒绝后处理。

---

## 1. 需要申请用户信息业务背景和理由

久窝朋赞会支付宝小程序服务于民宿/酒店旅客自助入住。旅客入住期间需通过小程序完成住宿实名登记，并在核验通过后使用智能门锁（蓝牙开锁）进入房间。

根据旅馆业住宿实名登记及门锁安全管理要求，系统必须确认「当前操作人」与「入住登记身份」一致，才能开放门锁控制与完整入住信息。因此需要申请支付宝实名三要素信息（姓名、身份证号、手机号），用于：

1. 完成住宿入住实名登记；
2. 核验入住人身份真实性与一致性；
3. 在身份核验通过后，向旅客开放蓝牙开锁/门锁密码等敏感能力，保障房东财产与住客安全。

如无法获取经核验的实名信息，则无法安全开放门锁权限，也无法满足住宿实名管理要求。

## 2. 产品逻辑

### 2.1 具体什么功能会要求用户进行授权；如同时申请多个字段，请明确不同功能需要的不同用户信息

触发授权的功能入口：

- 页面：进行中订单详情
- 操作：旅客点击「实名认证」按钮
- 前置状态：订单展示「未认证」

本次申请字段与用途对应关系如下：

| 申请字段 | 对应功能 | 用途说明 |
|---|---|---|
| 姓名 | 入住实名认证、住宿登记 | 确认入住人真实姓名，写入入住身份信息 |
| 身份证号 | 入住实名认证、住宿登记、门锁权限开通前置校验 | 确认入住人证件身份，作为实名一致性核验关键字段 |
| 手机号 | 入住实名认证、住宿联系与核验 | 确认入住人联系方式，完成三要素一致性核验 |

说明：上述三个字段均服务于同一核心功能「入住实名认证」。该功能通过后，才会开放后续「蓝牙开锁 / 门锁权限」能力。不另申请与本功能无关的用户信息字段。

### 2.2 用户授权后提供给用户的服务是什么

用户同意授权并完成实名三要素核验后，小程序将为用户提供：

1. 自动带入实名信息，完成入住实名认证；
2. 订单状态由「未认证」更新为「已认证」；
3. 开放智能门锁相关服务，包括「蓝牙开锁」等自助入住能力；
4. 展示完整入住所需信息（如门锁权限、入住指引等），方便旅客顺利入住。

简而言之：授权并核验通过后，用户可完成实名入住，并自助开锁入住。

### 2.3 如果用户拒绝，那么应用是否会提供给用户自行输入信息的功能；如果不允许用户自行输入，原因是什么

会提供自行输入信息的功能。

若用户拒绝支付宝实名信息授权：

1. 小程序不强制反复弹窗；
2. 引导用户进入实名认证页，允许手动填写姓名、身份证号、手机号；
3. 用户仍可提交信息进行住宿登记处理；
4. 但在身份核验未通过前，不开放「蓝牙开锁」等敏感门锁能力，以避免未核验身份获得开门权限。

即：拒绝授权不影响用户选择手动录入；但门锁等高敏感服务必须以身份核验通过为前提。

## 可直接粘贴到申请表的精简版

**1. 业务背景和理由**  
久窝朋赞会支付宝小程序用于民宿/酒店旅客自助入住。旅客需完成住宿实名登记，并在核验通过后使用蓝牙开锁进入房间。为满足旅馆业实名管理及门锁安全要求，需申请支付宝实名三要素（姓名、身份证号、手机号），用于确认操作人与入住身份一致，并在核验通过后开放门锁权限。

**2.1 授权功能与字段**  
进行中订单页点击「实名认证」时发起授权。姓名、身份证号、手机号均用于同一功能「入住实名认证」：姓名用于登记真实姓名，身份证号用于证件身份核验，手机号用于联系方式与三要素一致性核验。核验通过后开放蓝牙开锁。

**2.2 授权后服务**  
用户授权并核验通过后，完成入住实名认证，订单状态变为「已认证」，并可使用蓝牙开锁等自助入住服务。

**2.3 拒绝后处理**  
用户拒绝授权后，应用提供手动填写姓名、身份证号、手机号的功能，不强制反复弹窗；但在身份核验未通过前，不开放蓝牙开锁等敏感能力。
